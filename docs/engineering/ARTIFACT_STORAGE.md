# Immutable artifact storage and safe ingress

**Established by:** Prompt 06
**Authority:** `gateway/internal/objectstore/` and `gateway/ingest.go` are the
implementation; this document describes them. Where they disagree, the code is
correct and this file is a defect.

## What this replaces

The previous ingress had five distinct problems in about forty lines:

| Behaviour | Consequence |
|---|---|
| `io.ReadAll(file)` | the whole artifact in memory; no size bound on `ingest-raw` at all |
| `storage_path = "/s3/incoming/" + filename` | a storage path derived from client input, for an object that was never written |
| the file body persisted into a database column | raw financial content in the wrong store |
| a new row per delivery | a partner's retry became a second artifact |
| a synchronous validation verdict in the response | a slow parse was a slow request, a failed parse a failed upload |

No object was ever written anywhere. `storage_path` was a string that looked
like a location.

## Object keys

Keys are generated by the server: `tenant/<tenantID>/<yyyy>/<mm>/<dd>/` plus 128
bits from `crypto/rand`. **No part of a key comes from the caller.**

This is the difference between filtering path traversal and making it
unrepresentable. `../../../../etc/passwd` as a filename cannot influence where
anything lands, because the filename is not an input to the key function.
`TestUploadFilenameCannotInfluenceTheObjectKey` asserts this against five
hostile names.

A derived artifact — a repair — gets a *fresh* random key, not a decoration of
its source. `source-key.repaired` would make the relationship a string
convention that something would eventually parse, and would put the derived
object one character away from overwriting its source.

### Filenames

The client's filename is a display label and nothing else. It is normalised
(directory components stripped, control characters and NUL removed, leading dots
trimmed, length bounded) and both forms are stored, with a flag when they
differ — a legitimate client does not send control characters, so a `true` there
is worth looking at.

One thing found while writing the tests, worth recording: Go's
`multipart.Part.FileName()` already passes the value through `filepath.Base`, so
a traversal attempt reaches the handler already stripped. The defence is
therefore doubled. But it also meant the audit trail would have recorded a name
the client never sent, so `declaredFilename` reads the raw `Content-Disposition`
parameter to preserve what actually arrived.

## The two adapters

Both satisfy one interface and are checked by one conformance suite. A contract
verified against a single implementation is a description of that
implementation.

| Adapter | Use | Immutability mechanism |
|---|---|---|
| `FilesystemStore` | local development | `os.Link` to the final name — refused at the syscall |
| `S3Store` | production | stat-then-put, plus 128-bit random keys |

The difference is real and is not glossed in the code. The filesystem adapter's
create-if-absent is atomic; S3 has no portable equivalent, so `S3Store` has a
time-of-check-to-time-of-use gap. What makes an overwrite infeasible there is
that a second writer would have to guess a 128-bit key.

**Durable S3 immutability is a bucket property, not an application one.** A
production bucket needs versioning and Object Lock in compliance mode. This code
does not configure or verify either, and cannot — a client with `PutObject` and
`GetObject` rights cannot read a retention policy. It is deployment
configuration and it is not done.

### Why uploads stage to a temporary file

The obvious implementation streams the request body straight into `PutObject`
with an unknown length. It was written that way first and the conformance suite
rejected it, for two reasons:

1. The upload begins before the payload is known to be complete, so a client
   that disconnects halfway leaves a partial object in immutable storage. A
   truncated NACHA file parses — it simply describes fewer payments.
2. An unknown length forces minio-go into streaming SigV4, whose chunk framing
   is not decoded identically by every S3-compatible implementation. The test
   server stored the raw chunk envelope.

Staging to a temporary file fixes both. The copy uses a 32 KiB buffer, so memory
stays flat regardless of artifact size — the requirement is bounded memory, not
zero disk. The cost, stated plainly: an upload needs transient local disk equal
to the artifact, and the object reaches the bucket after the client finishes
rather than during.

## Ingress

Order of operations, and each step is there because skipping it was a defect:

1. **Authorize** — `artifact:upload`, tenant from verified claims.
2. **Bound** — `http.MaxBytesReader` before anything reads. The limit is the
   server's, so a lying `Content-Length` buys nothing.
3. **Stream the part** — `multipart.Reader`, not `ParseMultipartForm`, which
   buffers every part before the handler sees anything.
4. **Check quota** — before the bytes are accepted, not after. Checking
   afterwards means storing an object to discover it is not allowed.
5. **Measure while storing** — SHA-256, byte count and media sniff computed from
   the bytes actually received.
6. **Record and enqueue in one transaction** — both or neither. An artifact with
   no job is a file nobody will look at; a job with no artifact is a worker that
   fails forever.
7. **Return 202** with identifiers and measured facts, and **no verdict**.

The response deliberately carries no `isBalanced`, `RELEASED`, `VALIDATED`,
`findings` or `totalRecordsParsed`. A test asserts each of those strings is
absent, because that is the exact shape of the original defect.

### Idempotency

The fingerprint is `SHA-256(tenant ‖ filename ‖ size ‖ content hash)`.

- **No `Idempotency-Key` header** → the fingerprint is the key, so redelivery of
  identical content is idempotent by default.
- **Same key, same fingerprint** → replay; the original identifiers are
  returned with `duplicate: true`.
- **Same key, different fingerprint** → `409 idempotency_key_conflict`.
  Returning the first artifact would attribute one file's identity to another's
  bytes.

The filename is in the fingerprint deliberately: the same bytes under two names
are two deliveries. A partner sending yesterday's file again under today's name
is a real event that must not be silently collapsed.

A unique index on `(tenant_id, sha256_hash, size_bytes)` makes single-artifact-
per-content structural rather than conventional, whichever code path writes.

### Quotas

Per-tenant, on both total bytes and artifact count. A byte quota alone would not
notice a tenant uploading a billion one-byte files, which exhausts the database
rather than the object store. Defaults apply absent a `tenant_quotas` row; the
refusal message reports only the asking tenant's own numbers.

## Reading raw bytes

`GET /api/v1/artifacts/{id}/content` requires `evidence:read` — a higher bar
than listing artifacts — and streams through an audited proxy.

A short-lived signed URL was the alternative. The proxy was chosen because it
keeps the object store unreachable from the internet, and because every byte
served is attributable to a verified actor: a signed URL, once issued, is a
bearer token that can be forwarded, and the store cannot report who eventually
used it.

Every read writes an `artifact_access_log` row — actor, action, bytes served —
and the table is append-only by trigger. A cross-tenant request returns a
byte-identical response to a nonexistent id.

## Threat tests

| Case | Expected | Test |
|---|---|---|
| Empty file | 400 `empty_artifact`, no row, no object | `TestUploadRefusesAnEmptyFile` |
| Oversized file | refused, no row | `TestUploadRefusesAnOversizedFile` |
| Path traversal filename | key unaffected, name sanitised, original retained | `TestUploadFilenameCannotInfluenceTheObjectKey` |
| Duplicate | one artifact, `duplicate: true` | `TestDuplicateDeliveryIsIdempotent` |
| Conflicting duplicate | 409, original untouched | `TestConflictingIdempotencyKeyIsRejected` |
| Interrupted upload | no artifact, no job, no object | `TestInterruptedUploadLeavesNothingBehind` |
| Length mismatch | 400 `size_mismatch` | `TestContentLengthMismatchIsRefused` |
| Archive | stored as received, never expanded | `TestArchivesAreNotDecompressed` |
| Unauthorized object access | 404, indistinguishable from absent | `TestDownloadingAnotherTenantsArtifactIsIndistinguishableFromAbsent` |
| Storage unconfigured | 503, never a fallback | `TestUploadsAreRefusedWhenStorageIsUnconfigured` |

Archives are not decompressed at all, so a decompression bomb is simply a large
file and the byte limit applies. The test asserts the stored size equals the
uploaded size, which is the property that matters: nothing expanded it.

## Memory measurement

`TestUploadMemoryDoesNotScaleWithArtifactSize` uploads 256 KiB and 8 MiB and
compares allocation.

```
allocation: 256KiB upload=360,904 bytes, 8MiB upload=8,470,176 bytes, ratio=23.5x
payload ratio: 32x
environment: linux/amd64, go1.25.8
```

The 8 MiB figure is dominated by the test's own fixture, which the test
allocates before uploading. What the numbers show is that a 32× larger artifact
did not produce a 32× larger allocation in the handler.

**This is one measurement, of this process, on this machine, for this fixture.**
It is not a throughput figure, a capacity figure, or a claim about any other
environment. The requirement was to prove memory does not scale with artifact
size, and the ratio is what shows that.

## What is not done

1. **`POST /files/ingest-raw` is unchanged.** The JSON path still calls
   `ProcessFileBytes`, which reads the whole body into memory, writes no object,
   and returns a synchronous verdict. It is the path the UI uses. Prompt 07
   rewrites the validation pipeline and is where the two paths converge; until
   then the safe ingress and the old one both exist, and only `/files/upload` is
   safe.
2. **Nothing consumes the queued job.** `ingestion_jobs` rows are created and
   nothing leases them, so an uploaded artifact stays `RECEIVED` forever.
   Validation is Prompt 07; the durable worker is Prompt 08.
3. **Object Lock and versioning are not configured or verified.** See above.
4. **Detached-signature metadata is not implemented.** The guide lists it as
   optional; PGP verification exists in `security.go` and is not wired to
   ingest.
5. **No per-tenant rate limit on uploads.** The quota bounds total storage, not
   request rate. A tenant can still make many small uploads quickly.
6. **The S3 adapter is verified against gofakes3, not MinIO or AWS.** What that
   leaves unverified is listed at the foot of `conformance_test.go`: real
   multipart edge cases, TLS to a real endpoint, and concurrent writes to one
   key.
7. **Raw financial content is still stored in the database elsewhere.**
   `validation_findings.raw_data` holds full 94-character records and
   `GET /api/v1/incidents` returns them. That is baseline item P0-11 and is
   untouched by this work.
