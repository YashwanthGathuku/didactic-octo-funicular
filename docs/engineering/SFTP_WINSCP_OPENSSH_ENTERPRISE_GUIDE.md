# Enterprise WinSCP & OpenSSH Ingress Automation with Autonomous Agents

## 1. Executive Summary & Enterprise Reality

In institutional banking, treasury management, and custody networks, the vast majority of counterparties and enterprise batch jobs exchange ACH and wire files using:
1. **WinSCP** (on Windows Server, scheduled via Windows Task Scheduler or enterprise schedulers like Control-M / Autosys).
2. **OpenSSH / sftp / scp** (on Linux/UNIX mainframes and batch clusters).

Integrating enterprise WinSCP and OpenSSH clients safely requires solving real-world operational failure modes and leveraging autonomous AI agent diagnostics to eliminate manual incident friction.

---

## 2. Core Operational Pain Points & Solutions

### 2.1 The "In-Flight Transfer" Race Condition
* **The Problem**: When WinSCP or OpenSSH begins streaming a 500 MB NACHA file, the file appears in the filesystem immediately. If a downstream pipeline starts parsing before transfer completion, it crashes with premature EOF or parses truncated balances.
* **The Solution & Protocol Invariant**:
  - WinSCP writes to `filename.filepart` and renames to `filename` upon complete closure (`-resumesupport=on`).
  - OpenSSH clients write to `filename.part` or `.filename.tmp` and atomically rename upon completion.
  - SentinelFlow's ingress validator strictly rejects `.filepart`, `.part`, and `.tmp` files (`gateway/internal/sftp/event.go`), ensuring ingestion occurs **only upon atomic rename completion**.

### 2.2 SSH Key Format Mismatches
* **The Problem**: Windows teams generate PuTTY Private Keys (`.ppk` v2/v3), while Linux servers and cloud gateways expect OpenSSH PEM format (`-----BEGIN OPENSSH PRIVATE KEY-----` or PKCS#8). This causes silent authentication failures and urgent ticket escalation.
* **The Solution**: SentinelFlow's diagnostic engine (`InspectSSHKey`) parses raw key headers non-destructively, identifies the format, and provides exact, automated conversion instructions (e.g. `puttygen -O private-openssh`).

### 2.3 Stale Locks & Interrupted Transfers
* **The Problem**: A network glitch drops a WinSCP upload mid-transfer, leaving an orphaned `.filepart` lock on disk that prevents future scheduled runs from executing.
* **The Solution**: The autonomous reconciliation scanner (`ScanStaleLocks`) detects abandoned locks older than 30 minutes, flags the stalled transfer, and alerts operators without manual filesystem triage.

## 4. Hardened WinSCP Automation Script Reference

For automated banking batch transfers, use the following production-hardened WinSCP script template generated by SentinelFlow:

```ini
# SentinelFlow WinSCP Automated Ingestion Script
# Enforce abort on any batch error
option batch abort
option confirm off

# Connect using PuTTY PPK private key authentication and strict hostkey checking
open sftp://svc_treasury@sftp.meridian.bank:2222/ -privatekey="C:\keys\treasury.ppk" -hostkey=*

# Enforce binary transfer mode and temporary .filepart extension for atomic upload
option transfer binary
option resume off

# Upload files with temporary extension (WinSCP automatically renames on complete)
put -resumesupport=on "D:\Outbound\*.ach" "/inbound/ach/"

# Close session cleanly
exit
```
